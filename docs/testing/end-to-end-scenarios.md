# End-to-End Scenarios

These are verification journeys derived from linked authorities, not claims of Playwright coverage. A run needs isolated [test data](test-data-catalog.md) and established [prerequisites](dependency-graph.md). Observe server outcomes as well as browser presentation for access, payment, and protected data. Exact route/screen states belong to [Frontend screen contracts](../frontend/screen-contracts/screen-index.md); HTTP operations belong to [OpenAPI](../api/openapi.yaml).

| Journey | Authority and prerequisites | Observable outcome |
|---|---|---|
| Account creation, verification, sign-in | [Accounts requirement](../product/requirements.md); test email delivery and new actor account. | The actor completes the approved account path and reaches only allowed capabilities. |
| Account/password recovery | [Accounts requirement](../product/requirements.md), [Security](../security/authentication-authorization.md); test inbox and account. | Account access is recovered; token/session effects conform to Security. |
| Nurse profile and recruitment contact | [Roles](../product/roles-and-permissions.md), [contact rule](../product/business-rules.md); distinct nurse and employer. | Employer requests contact; protected data is withheld until nurse approval. |
| Mock exam and result | [Exam requirements](../product/requirements.md), [business rules](../product/business-rules.md); eligible exam and nurse. | The nurse runs an allowed session and obtains its finalized outcome. |
| Standalone exam purchase | [Product requirements](../product/requirements.md), [business rules](../product/business-rules.md); offer and payment test boundary. | Successful fulfillment grants standalone access without becoming a package right. |
| Preparation Package publication, purchase, and repurchase | [Package rules](../product/business-rules.md), [architecture flow](../architecture/runtime-flows.md); authorized administrator, published exam/content, compatible reporting profile, package version, offer, and payment test boundary. | Fulfillment produces a nurse-owned entitlement and starts its access window; active same-package entitlement blocks repurchase, while post-expiry repurchase creates a separate right. |
| Package materials and practice | [Package requirement](../product/requirements.md), [package rules](../product/business-rules.md); entitled nurse and active window. | Included materials and independent practice are accessible. Learner material delivery is an implementation gap to measure, not grounds to erase this scenario. |
| Package attempt and numeric report | [Package requirements](../product/requirements.md), [business rules](../product/business-rules.md); entitled nurse, eligible exam, finalized qualifying session. | Failed start leaves the attempt unused; same-source retry resumes a valid session; a started session can finalize after package expiry. Its qualifying finalization yields one recoverable, immutable report right; numeric exam evidence, topic results, and purchased-content guidance appear without qualitative bands or protected question detail. |
| Authorized administration | [Roles](../product/roles-and-permissions.md), [Security verification](../security/security-verification.md); authorized and unauthorized actors. | Permitted changes succeed; server denies unauthorized protected operations. Promotion administration is checked only at approved capability level, not unapproved calculation mechanics. |

Current `frontend/playwright.config.ts` selects authentication specs only. Historical scenario catalogs model broader journeys; their presence is not evidence that these journeys are automated or passing.
